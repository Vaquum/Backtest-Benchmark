# Safety assessment of the pinned comparison cohort

The useful safety comparison is a set of scoped contracts, not a ranking by test count or a single safety score. The matrix contains **195 candidate–criterion cells, covering 13 candidates and S01–S15, with 465 commit-pinned code references**. Each cell states its threat model, actual route, enforcement status, applicability, evidence class and limitation. The frozen Limen cells retain the prior review's evidence rather than inheriting new candidate test claims.

Executable implementation, executable configuration, test assertions and retained local probe results are the evidence. README prose, comments, docstrings and feature names do not establish behavior. A source build proves that build completed in its recorded environment; it does not prove every boundary safe. The [canonical safety matrix](../assessment/safety.json) and [reusable scope/protocol overrides](../assessment/safety_protocol_overrides.json) retain the detailed contracts.

## Fair scope and threat models

Four distinctions matter throughout this assessment. First, a researcher supplying ordinary Python or compiled strategy code is a trusted-code caller. Dynamic imports and callbacks are expected in that model. They become a failed constrained boundary only when an actual guarded interface purports to limit what supplied configuration can resolve or execute. Second, authenticated access does not isolate mutually hostile users, and local artifact ownership remains relevant even behind authentication. Third, thread/process failures, partial writes and restart are different from adversarial remote compromise. Finally, simulator affordability and protective-exit rules are economic model properties; they do not establish live exchange loss limits or guaranteed fills.

`Enforced` is conditional on the named route and settings. `Optional` identifies a control that must be enabled or registered. `Partial` means the observed contract covers some relevant paths or cases. `Fails` requires a scoped counterexample or direct implementation contradiction; the evidence class states whether it was executed. `Unknown` records the exact bounded inspection that did not establish a capability. `N/A` applies to an explicitly chosen track, not to the project's overall quality.

An in-memory execution library can have S05/S06/S07/S13 marked N/A with `adapter_required` because the selected route does not implement a managed study manifest, immutable research rounds, durable experiment restart or protected holdout governance. A full comparison with Limen's research workflow must add and audit that layer. It cannot count N/A as a pass. The specialist hftbacktest route similarly accounts for fills and PnL; a capital-admission adapter is required before imposing a cash-only S11 contract. ([hftbacktest/src/backtest/state.rs:22–55](https://github.com/nkaz001/hftbacktest/blob/5f3ec40b2afb764e0fea112f941ed85523ef4e88/hftbacktest/src/backtest/state.rs#L22-L55))

**hftbacktest — malformed-reader liveness, inspected only.** Generic `read_npy` repeatedly adds the returned byte count until a declared size is reached and does not handle `Read::Ok(0)`. ## Assurance limits and repetition

New concrete runtime evidence consists of the bounded [QSTrader](../results/probes/qstrader_boundaries.json), [Qlib](../results/probes/qlib_async_boundary.json), [LEAN](../results/probes/lean_unzip_boundary.json) and [backtesting.py](../results/probes/backtesting_trailing_prefix.json) probes, plus the separately recorded [hftbacktest native backtest-library campaign](../results/native_checks/hft_frozen_dependencies/hftbacktest.json): 22 tests passed, including queue/depth/event assertions. That test set did not exercise the malformed-reader counterexamples. Other cited alternative-candidate safety assertions were inspected, not run as a comprehensive security campaign. Frozen Limen's selected tests retain their own prior scope. No global fuzz, mutation, multiwriter, power-loss or live-exchange campaign was completed, and hosted CI enforcement was not inferred from workflow files.

These safety results are independent of the execution-timing campaigns. The [preserved original campaign's thread configuration](../results/campaigns/2026-10-19-common-zero-original/benchmark-source/bench/provenance.py) did not explicitly constrain Polars. A corrective thread-control run is a separate campaign; timing tables must identify their campaign, and its samples cannot be pooled with the original samples. This report uses neither campaign's latency as evidence of a safety property. The [probe wrapper revision record](../results/probes/probe_admission_revision.json) likewise distinguishes the original observed results from later admission-check improvements without replacing those results.

For repetition, select the required track and supported entry point first, then declare the economic/information/persistence contract. Compare candidate and Limen only after matching source/data identity, timestamps, warmup, fee/borrowing semantics, execution price, queue/volume assumptions and optional controls. Re-run a shared applicable boundary corpus under bounded external resources. Keep unmeasured quantities blank, preserve Unknown and N/A, and report failures by reachable route. The 15 protocol overrides specify those acceptance experiments generically so a later candidate is assessed against the same contract rather than against Limen's internal filenames.
