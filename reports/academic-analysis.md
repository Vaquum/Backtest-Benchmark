# Academic rigor and robustness: comparison findings

## Reading this assessment fairly

The canonical comparison contains 195 academic rows: 15 criteria for each of 13 pinned candidates. Its evidence is executable source, configuration consumed by code, test assertions, and retained local experiment results. Source-inspected tests establish that a project contains a particular assertion; they are not represented as tests executed in this comparison. No candidate's complete test suite or real-market validity is inferred from these bounded checks.

The capability boundary is essential. Qlib and Freqtrade's FreqAI paths own model fitting and dated evaluation, making them direct peers for parts of Limen's research workflow. LEAN, bt, and Zipline also contain native rolling portfolio or statistical estimators, which merit review of their fit windows. Generic replay engines receive an adapter requirement for supervised labels, nested preprocessing, or a reserved research holdout when those facilities are outside the inspected native execution layer. An N/A row means that scope must be supplied elsewhere to compare complete research platforms. Unknown means the evidence does not establish the requested property, including bounded searches that did not locate a capability. Neither means that a framework has been proved incapable of hosting an implementation.

Statuses therefore describe a named path and property, rather than a universal product grade. Optional identifies a callable diagnostic or analysis path; Enforced is reserved for a guard actually applied in its stated path; Partial records implemented support with material coverage limits; Fails requires a concrete violation of the stated property. A count of green rows, numerical conversion of these statuses, or average across native and adapter requirements would conceal the capability differences. All A14 external-validity rows remain Unknown: the inspected code and bounded fixture runs do not establish generalization across markets, regimes, or real exchange behavior.

## Findings that materially change the Limen comparison

Three causal counterexamples were reproduced on unchanged recorded prices, each with a different scope. Limen's batch feature can revise historical feature rows after future extension. backtesting.py's native percentage trailing-stop helper can revise a historical decision coefficient after future extension. Its per-bar `next` loop restricts visible data and registered indicators, while `init` sees the full batch. QSTrader's native prehistory getter can return the final future observation. These are reproducible interface violations; they are not estimates of how frequently an arbitrary strategy fails or how much its P&L changes.

Native statistical support also differs meaningfully. Limen and vectorbt implement deflated-Sharpe diagnostics. LEAN implements probabilistic Sharpe against a fixed benchmark. Jesse implements an optional stationary-bootstrap rule test. These methods answer different questions, use different assumptions, and provide different evidence about dependence and selection. A helper's presence is not proof that every candidate is admitted through it or that its probability output is calibrated after adaptive research. Limen's restricted holdout reservation and exposure record are distinctive implemented controls in the inspected cohort, but several of its own research paths cannot use that protocol.

Cross-engine native metric labels are insufficient for academic comparison. The benchmark should derive its declared common quantities from the same ordered cash, inventory, fills, and equity observations, while preserving each native metric's separate meaning. The candidate sections below identify examples that make this requirement concrete.

## backtesting.py

During per-bar `next` calls, the core runner restricts visible data and registered indicators to the current prefix. The `init` callback receives the full batch. Its native `TrailingStrategy` helper has a separate failure: `set_trailing_pct` computes a percentage-to-ATR multiplier using the entire init sample, and ATR itself backfills its initial incomplete window. On the unchanged recorded fixture, extending 192 rows to 384 changed the native multiplier from 12.534609847694947 to 11.750024076167358. The native ATR arrays were identical on the common prefix, while implied historical stop distances changed on all 153 fully observable rows after excluding the first 39 warmup rows. The first mature divergence was 152 rows before the prefix ended; a fixed-six-ATR control changed no rows. [backtesting/backtesting.py:1321–1354](https://github.com/kernc/backtesting.py/blob/ca2e2611621e472542ba90f7243a1fa06a7d7108/backtesting/backtesting.py#L1321-L1354) [backtesting/lib.py:471–474](https://github.com/kernc/backtesting.py/blob/ca2e2611621e472542ba90f7243a1fa06a7d7108/backtesting/lib.py#L471-L474) [backtesting/lib.py:492–506](https://github.com/kernc/backtesting.py/blob/ca2e2611621e472542ba90f7243a1fa06a7d7108/backtesting/lib.py#L492-L506)

The portable probe executes the public `Backtest.run` path and reads the native helper state. It places no orders and makes no realized P&L or defect-frequency claim. The retained JSON is `results/probes/backtesting_trailing_prefix.json`. Restricting the per-bar `next` prefix cannot repair a coefficient that was already fitted using future `init` observations, which is the precise reason A01 fails for this helper.

Grid/SAMBO optimization selects among results on the same supplied data; optional heatmaps and optimizer details provide a local search record. The native buy-and-hold comparison starts after the strategy's warmup, so parameter-dependent warmup can change the evaluation interval. Native Sharpe uses a geometric annual-return/compounded-volatility convention rather than a shared arithmetic mean/sample-volatility definition. These details require a common external return tape. ## Implications for the repeatable protocol

The comparison should ask four questions of each capability: which component owns it, what exact inputs it consumes, which constraint is actually enforced, and what evidence was retained. A mandatory guard in a narrow native path is stronger evidence for that path than a broadly available helper, but unsupported paths remain visible. Likewise, a reproduced counterexample invalidates its stated interface property while leaving unrelated components available for separate assessment.

The proposed generic A01–A15 scopes and protocols are saved in `assessment/academic_protocol_overrides.json`. They retain the canonical definitions while removing Limen-specific class names. They require actual post-transform observation identities, appropriate label-completion times, local fit support, complete declared selection history, explicit dependence assumptions, compatible return conventions, and honest final-data exposure labels. They distinguish implementation parity from independent mathematics, probability calibration, and empirical market fidelity.

The common execution benchmark supplies another, narrower evidence track. Its independent cash/quantity oracle validates declared lagged decisions, fills, and after-fill equity against each adapter's observed output. That evidence should not be promoted into proof of a native ML workflow, market-impact accuracy, or a protected research holdout. Optional output fields are checked only where a native observation exists; reconstructed held-segment fills are explicitly weaker evidence than a native order ledger. Component-only drivers remain outside full-engine duration ratios. These boundaries preserve the practical value of both the numerical benchmark and the academic grid.
